# AnimeVault

Личная PWA-библиотека аниме: локальная база IndexedDB, облачная синхронизация через Supabase, постеры в Google Drive и поиск метаданных по нескольким каталогам.

## Возможности

- Библиотека с карточками и компактным списком, поиском, избранным и фильтрами по статусу, жанру, формату, году и наличию постера/метаданных.
- Ручное добавление и редактирование карточек, прогресс серий, ссылка на просмотр.
- Метаданные из AniList, Shikimori и Kitsu: жанры, формат, год, количество серий, длительность, оценка, описание и постер.
- Фильтр жанров получает список из API и сохраняет его в локальном кеше.
- Автоматического перевода описаний нет. Описания, уже сохранённые в библиотеке, не удаляются; новые описания берутся в исходном виде из каталога.
- Локальная IndexedDB для офлайн-работы.
- Облачная синхронизация записей через Supabase Auth и таблицу `public.animevault_records` с RLS.
- Постеры сохраняются в личную папку Google Drive **AnimeVault Posters**; локальные Blob-копии позволяют показывать уже загруженные постеры офлайн.
- CSV импорт/экспорт и полный JSON-бэкап.
- PWA-установка на поддерживаемых браузерах.

## Архитектура и данные

- **IndexedDB/Dexie** — основная локальная библиотека. Очистка данных браузера может удалить локальные записи, поэтому регулярно создавайте JSON-бэкап.
- **Supabase Auth + Postgres** — вход в AnimeVault и синхронизация записей между устройствами. Доступ к строкам ограничен владельцем через RLS.
- **Google Drive** — хранение новых облачных постеров. Для подключения используется Google Identity Services с OAuth scope `drive.file`; токен Drive хранится только в памяти вкладки и после перезагрузки подключение требуется повторить.
- **AniList / Shikimori / Kitsu** — внешние источники метаданных. Поиск требует интернет-соединения; уже загруженные сведения доступны офлайн.
- Старый публичный bucket Supabase Storage оставлен для совместимости со старыми URL, но новые постеры загружаются в Google Drive.

## Запуск и публикация

Приложение размещено на GitHub Pages:

https://maestro-777.github.io/anime-tracker.github.io/

Для локального запуска на Windows используйте `start.bat` (нужен Python) либо любой локальный HTTP-сервер. Не открывайте `index.html` через `file://`: Service Worker и установка PWA требуют HTTPS или localhost.

## Вход и Google Drive

Вход в AnimeVault выполняется через Supabase Auth: email + пароль или GitHub OAuth. Google OAuth используется отдельно — только для доступа к Google Drive, а не для входа в AnimeVault.

Для Google OAuth типа Web application в Google Cloud Console должен быть указан Authorized JavaScript origin:

`https://maestro-777.github.io`

Указывать путь репозитория в origin не нужно. Для режима Testing также добавьте нужный Google-аккаунт в Test users. Client ID публичен и используется в браузере; Client Secret в клиентский код добавлять нельзя.

Инструкции по настройке Drive: [GOOGLE_DRIVE_SETUP_RU.md](GOOGLE_DRIVE_SETUP_RU.md).

## Supabase

SQL для первоначальной настройки находится в [SUPABASE_SETUP.sql](SUPABASE_SETUP.sql). В проекте используются Edge Functions:

- `fetch-anime-metadata` — прокси поиска по AniList, Shikimori и Kitsu, а также диагностика API и получение жанров.
- `fetch-poster` — безопасная загрузка постеров с разрешённых источников.
- `fetch-anime-description` — выведена из эксплуатации и возвращает HTTP 410; приложение её не вызывает.

Все активные функции требуют JWT. Публичный клиент использует только publishable key; `service_role` и секреты не должны попадать в браузер.

## Резервное копирование и перенос

- Используйте **Бэкап JSON** для полной копии карточек и метаданных.
- CSV предназначен для переноса и редактирования основных полей и метаданных.
- Для облачной синхронизации войдите в один и тот же аккаунт AnimeVault на устройствах.
- Для синхронизации постеров дополнительно подключите Google Drive на каждом устройстве, где нужно загружать или просматривать новые Drive-постеры.
- Не удаляйте старые файлы и bucket до проверки библиотеки на всех устройствах.

## Разработка

Основные файлы:

- `index.html` — интерфейс и стили.
- `app.js` — логика приложения, IndexedDB, API, синхронизация и Drive.
- `sw.js` — кеш оболочки и офлайн-поведение.
- `manifest.json` — метаданные PWA.
- `supabase/functions/` — Edge Functions.
- `supabase/migrations/` — миграции базы данных.

После изменения оболочки приложения увеличивайте `CACHE_NAME` в `sw.js`, чтобы установленные PWA получили новую версию.
