# AnimeVault — оптимизация синхронизации и русские описания

## Что изменено

- IndexedDB остаётся локальным источником данных. Индекс `recordUuid` уже существовал в схеме Dexie v7/v8; синхронизация теперь использует его через `where('recordUuid').equals(...)`, а не повторный линейный поиск.
- Локальные изменения отмечаются в самой записи IndexedDB полем `syncDirty`; отметка снимается только после успешной отправки той же версии записи. Поле индексировано.
- Удаления по-прежнему сохраняются как `tombstone:<recordUuid>` и отправляются отдельно. Удаление с другого устройства применяется без создания нового локального tombstone.
- После первой полной синхронизации Supabase читаются только строки новее сохранённого курсора `lastSync:<userId>` (с перекрытием 2 секунды для одинаковых/пограничных timestamp).
- Запросы Supabase с временными сетевыми ошибками, HTTP 408/425/429/5xx повторяются до трёх раз с увеличивающейся задержкой.
- Автоматические события синхронизации объединяются через один планировщик; частые focus/visibility/online события не запускают параллельные проходы.
- Загрузка постеров переведена на индексированную очередь `posterPending`; старая библиотека однократно сканируется при первом подключении Drive.
- AniList GraphQL ищет до девяти названий алиасами в одном запросе. На последующих синхронизациях локально выбираются только записи с `syncDirty = 1`; изменения из облака сопоставляются по индексу `recordUuid`.
- Русские описания сначала запрашиваются из Shikimori. Если описание там не найдено, исходный текст переводится на русский; результат сохраняется в `descriptionRu` и синхронизируется как часть обычной записи.
- CSV импорт/экспорт поддерживает отдельную колонку «Описание на русском».

## Развёртывание Edge Function для русских описаний

Новая функция: `supabase/functions/fetch-anime-description/index.ts`.

Из корня репозитория после получения ветки `feature/animevault-performance-russian`:

```bash
npx supabase login
npx supabase link --project-ref ytmnsnvxjhpejidcndyw
npx supabase functions deploy fetch-anime-description
```

Функция использует JWT AnimeVault (`verify_jwt = true`), публичный read API Shikimori и резервный Google Translate endpoint. Секреты и service-role ключ в браузере не нужны. Если резервный сервис перевода временно недоступен, запись помечается как ошибка и может быть повторно обработана.

## Проверка перед публикацией

1. Развернуть `fetch-anime-description` в Supabase.
2. Проверить, что в Supabase Edge Functions отображаются `fetch-poster` и `fetch-anime-description`.
3. Опубликовать изменения этой ветки через PR в `main`.
4. Обновить PWA жёсткой перезагрузкой.
5. Запустить «Обновить только непроверенные»: обработаются новые метаданные и записи без русского описания.
6. Проверить на двух устройствах: добавить запись на первом, изменить прогресс на втором, затем удалить запись на одном устройстве и убедиться, что удаление синхронизировалось.
7. Проверить офлайн-режим и кэш постеров до удаления старого Supabase Storage bucket.

## Безопасность и миграция

Старый bucket Supabase Storage и его политики намеренно не удаляются: старые ссылки могут ещё использоваться записями/устройствами. Удалять их можно только после проверки всех постеров на каждом устройстве и наличия Drive ID у перенесённых файлов.
